# Dialog

**วัตถุประสงค์:** หน้าต่างซ้อนบนหน้า ให้ผู้ใช้ทำงานสั้น ๆ หนึ่งงานให้เสร็จหรือปิดก่อนกลับไปที่หน้าเดิม

## ควรใช้เมื่อ

- งานสั้นที่ต้องการความสนใจเต็มที่และอยู่ในหน้าจอเดียว เช่น กรอกจำนวนเงินโอน เปลี่ยนชื่อ ฟอร์มเล็ก 1–3 ช่อง
- งานสั้นที่หน้าด้านหลังควรยังมองเห็นได้เพื่อเป็นบริบท

## ไม่ควรใช้เมื่อ

| แทนที่จะใช้ dialog กับ… | ให้ใช้ |
| ----------------------- | ------ |
| การยืนยันการกระทำที่ทำลายข้อมูลหรือมีผลสำคัญ ("Delete this account?") | **AlertDialog** |
| ข้อความแจ้งสำเร็จหรือข้อความที่ไม่สำคัญ | toast หรือข้อความในหน้า TODO: ยังไม่มีทั้งสองอย่าง |
| ข้อผิดพลาดของฟอร์ม | แสดงข้างช่องในหน้า ด้วย `invalid` ของ Input |
| งานยาว ซับซ้อน หลายขั้นตอน หรือตารางใหญ่ | หน้าแยก |
| การตัดสินใจที่ต้องดูเนื้อหาที่ dialog จะบัง | เนื้อหาในหน้า |
| การยืนยันการกระทำทั่วไปที่ย้อนกลับได้ | ทำไปเลย แล้วให้ undo |
| ข้อมูลอย่างเดียวที่ไม่มีอะไรให้ตัดสินใจ | เนื้อหาในหน้า อย่าขัดจังหวะ |
| การเปิดจาก dialog อื่น | หลีกเลี่ยงการซ้อน dialog ให้เปลี่ยนเนื้อหาหรือย้ายไปหน้าแยก ระบบส่วนใหญ่ห้าม GitHub Primer อนุญาตไม่เกินสองชั้น |
| เนื้อหาที่ต้องเลื่อนบนจอแล็ปท็อป | หน้าแยก dialog เลื่อนได้ แต่เป็นแค่ทางสำรอง |

## การเขียนเนื้อหา

- **หัวข้อ:** บอกว่าผู้ใช้กำลังทำหรือตัดสินใจอะไร เช่น "Transfer funds" หรือ "Delete this account?" หลีกเลี่ยงหัวข้อกว้าง ๆ เช่น "Warning!", "Error" หรือ "Are you sure?"
- **ปุ่ม:** ใช้คำกริยาเฉพาะที่สอดคล้องกับหัวข้อ ("Delete account", "Transfer") ไม่ใช่ "OK" หรือ "Yes / No"
- **จำนวนการกระทำ:** ปกติสองอย่าง คือการกระทำหลักหนึ่งอย่างและทางออกหนึ่งทาง ใช้สามอย่างเฉพาะบางครั้ง
- **ลำดับ:** ทางออกก่อน แล้วจึงการกระทำหลัก dialog จะวางการกระทำหลักไว้ทางขวาบนจอกว้าง และไว้บนสุดบนจอเล็ก
- **ต้องมีทางออกเสมอ:** คงปุ่ม × ไว้ หรือมีปุ่มแบบ Cancel ปุ่ม Esc ก็ใช้ได้เสมอ

## ส่วนประกอบ

ส่วนประกอบของ dialog จากบนลงล่าง

| ส่วน | หน้าที่ |
| ---- | ------- |
| **Dialog** | เก็บสถานะเปิด/ปิด ไม่ได้แสดงอะไรเอง |
| **DialogTrigger** | control ที่เปิด dialog มักแสดงเป็น Button |
| **DialogContent** | ตัวแผง มีฉากหลังมืดของตัวเอง และมีปุ่มปิด × เป็นค่าเริ่มต้น |
| **DialogHeader** | วางหัวข้อและคำอธิบายซ้อนกัน |
| **DialogTitle** | จำเป็น หัวข้อสั้นที่บอกชื่องาน โปรแกรมอ่านหน้าจอประกาศเมื่อเปิด |
| **DialogDescription** | ไม่บังคับ บริบทหนึ่งหรือสองประโยค ประกาศเมื่อเปิดด้วย |
| เนื้อหา | อะไรก็ได้ เช่น ช่องกรอก ข้อความ ไม่มีส่วนเฉพาะสำหรับเนื้อหา |
| **DialogFooter** | แถวปุ่มการกระทำ |
| **DialogClose** | ปิด dialog แสดงเป็น Button สำหรับ Cancel หรือการกระทำที่ปิดไปด้วย |

## การนำเข้าและใช้งาน

ติดตั้งแพ็กเกจ แล้วนำเข้า stylesheet **ครั้งเดียว** ที่ root ของแอป เช่น ใน `app/layout.tsx`

```bash
npm install @chonny_iamsrithong/lab-package
```

```tsx
import "@chonny_iamsrithong/lab-package/styles.css"
```

จากนั้นนำเข้า component ในไฟล์ที่ใช้

```tsx
import {
  Button,
  Dialog,
  DialogClose,
  DialogContent,
  DialogDescription,
  DialogFooter,
  DialogHeader,
  DialogTitle,
  DialogTrigger,
} from "@chonny_iamsrithong/lab-package"

<Dialog>
  <DialogTrigger render={<Button />}>Rename</DialogTrigger>
  <DialogContent>
    <DialogHeader>
      <DialogTitle>Rename account</DialogTitle>
    </DialogHeader>
    <DialogFooter>
      <DialogClose render={<Button variant="outline" />}>Cancel</DialogClose>
    </DialogFooter>
  </DialogContent>
</Dialog>
```

- นำเข้าเฉพาะส่วนที่ใช้ ปุ่มก็มาจากแพ็กเกจเดียวกัน
- Dialog มี `"use client"` มาในตัว dialog ที่แค่เปิดและปิดจึงใช้จาก Server Component ได้ ถ้าควบคุม `open` เอง หรือบันทึกฟอร์ม ไฟล์ต้องขึ้นต้นด้วย `"use client"`
- กำหนด `--font-heading` ในแอป เพราะหัวข้อใช้ฟอนต์นี้

## Props และ variants

Dialog **ไม่มี prop `variant` หรือ `size`** ทุก dialog ใช้แผงเดียวกัน ปุ่มข้างในใช้ variant ของ Button

### Dialog

| Prop | ค่าเริ่มต้น | ทำอะไร |
| ---- | ----------- | ------ |
| `defaultOpen` | `false` | เปิดตั้งแต่แรก dialog จัดการสถานะเปิดเอง |
| `open` + `onOpenChange` | ไม่มี | ให้แอปควบคุมว่าเปิดเมื่อไร เช่น ปิดเฉพาะเมื่อบันทึกสำเร็จ |
| `modal` | `true` | `true`: โฟกัสถูกล็อกไว้ หน้าเลื่อนไม่ได้ คลิกหน้าด้านหลังไม่ได้ `"trap-focus"`: โฟกัสถูกล็อก แต่หน้ายังเลื่อนและคลิกได้ `false`: หน้ายังใช้ได้ สำหรับเครื่องมือช่วยที่ใช้ควบคู่ เช่น ค้นหาและแทนที่ |
| `disablePointerDismissal` | `false` | เมื่อเป็น `true` การคลิกฉากหลังจะไม่ปิด dialog Esc, × และ Cancel ยังปิดได้ **ตั้งค่านี้กับทุก dialog ที่มีฟอร์ม** เพื่อไม่ให้คลิกพลาดแล้วสิ่งที่พิมพ์หายไป |

### DialogContent

| Prop | ค่าเริ่มต้น | ทำอะไร |
| ---- | ----------- | ------ |
| `showCloseButton` | `true` | แสดงปุ่ม × มุมขวาบน เป็นปุ่มไอคอน ghost ขนาดเล็ก มี label "Close" สำหรับโปรแกรมอ่านหน้าจอ |
| `initialFocus` | element แรกที่โฟกัสได้ | element ที่ได้โฟกัสเมื่อเปิด ปุ่ม × อยู่ท้ายสุด ใน dialog ฟอร์มช่องแรกจึงได้โฟกัส ตามที่ WAI-ARIA, IBM Carbon และ Microsoft Fluent แนะนำ เมื่อเปิดด้วยการแตะ ตัวแผงจะได้โฟกัสแทน แป้นพิมพ์บนจอจึงไม่เด้งขึ้นมา |
| `finalFocus` | ปุ่มที่เปิด | element ที่ได้โฟกัสคืนเมื่อปิด |

### DialogFooter

| Prop | ค่าเริ่มต้น | ทำอะไร |
| ---- | ----------- | ------ |
| `showCloseButton` | `false` | เพิ่มปุ่ม "Close" แบบ outline ต่อท้าย ใช้แทน × กับ dialog ที่อ่านอย่างเดียว |

### DialogTrigger และ DialogClose

ทั้งสองรับ `render` เพื่อแสดงเป็น Button เช่น `render={<Button variant="outline" />}` ใช้ variant ใดของ Button ก็ได้

### พฤติกรรมในตัว

- **การเปิด:** ฉากหลังและแผงค่อย ๆ ปรากฏใน 100ms ซึ่งอยู่ฝั่งเร็วของช่วงที่ Material และ Carbon ใช้ แผงขยายขึ้นเล็กน้อย TODO: แอนิเมชันยังเล่นแม้ผู้ใช้ตั้งค่าลดการเคลื่อนไหว WCAG กำหนดเรื่องนี้แค่ระดับ AAA
- **การปิด:** Esc, ปุ่ม ×, DialogClose ใดก็ได้ หรือคลิกฉากหลัง โฟกัสกลับไปที่ปุ่มที่เปิด
- **Layout:** แผงอยู่กลางจอ กว้างไม่เกิน 448px บนจอตั้งแต่ 640px และกว้างเต็มจอลบด้านละ 16px บนจอที่เล็กกว่า ระยะขอบ 24px และระยะระหว่างส่วน 24px
- **มีความกว้างเดียว** ระบบส่วนใหญ่มี 3–5 ขนาด และ GitHub Primer ทำ dialog ฟอร์มให้เต็มจอบนมือถือ TODO: ตัดสินใจว่า Dialog ต้องมีขนาดหรือโหมดเต็มจอบนมือถือหรือไม่

**เนื้อหาที่สูงจะเลื่อนภายในแผง** แผงไม่สูงเกินจอลบด้านบนและล่างด้านละ 16px เมื่อเนื้อหายาวกว่านั้น ทั้งแผงจะเลื่อน รวมหัวข้อและปุ่ม ทุกอย่างจึงยังเข้าถึงได้บนมือถือและที่การซูม 400% (WCAG 1.4.10 Reflow) การกด Tab ไปที่ปุ่มจะเลื่อนปุ่มเข้ามาในจอ

### ฟอร์มใน dialog

- **ครอบช่องกรอกและส่วนท้ายด้วยฟอร์มเดียว** และให้การกระทำหลักเป็น Button `type="submit"` แทน DialogClose แล้วการกด Enter ในช่องจะส่งฟอร์ม story `Playground` ไม่มีฟอร์ม Enter จึงไม่ทำอะไร
- **เปิด dialog ไว้จนกว่าจะบันทึกสำเร็จ** ควบคุมด้วย `open` และ `onOpenChange` แล้วปิดเองเมื่อสำเร็จ
- **แสดงข้อผิดพลาดใน dialog** ข้างช่อง ด้วย `invalid` ของ Input อย่าปิด dialog เพื่อแจ้งข้อผิดพลาด
- **ตั้ง `disablePointerDismissal`** เพื่อไม่ให้การคลิกฉากหลังทำให้สิ่งที่ผู้ใช้กรอกหายไป
- TODO: Dialog ยังไม่มีสถานะกำลังโหลดสำหรับปุ่มส่ง AlertDialogAction มี แต่ Dialog ยังไม่มี ระหว่างนี้ให้แอปป้องกันการกดส่งซ้ำเอง
- TODO: ยังไม่มีแนวทางสำหรับการถาม "Discard changes?" เมื่อผู้ใช้ปิด dialog ที่ยังมีข้อมูลไม่ได้บันทึก

### การยืนยันการลบหรือทำลาย

ใช้ **AlertDialog** กับการกระทำที่ย้อนกลับไม่ได้ เช่น ลบหรือเพิกถอน มันไม่ปิดเมื่อคลิกฉากหลัง และโปรแกรมอ่านหน้าจอประกาศเป็นการแจ้งเตือน ดูคู่มือของ AlertDialog

### การเข้าถึงที่ได้มาในตัว

- โฟกัสเข้าไปใน dialog เมื่อเปิด อยู่ข้างในขณะเปิด และกลับไปที่ปุ่มที่เปิดเมื่อปิด
- Esc ปิด dialog
- หัวข้อเป็นชื่อของ dialog และคำอธิบายบรรยาย dialog สำหรับโปรแกรมอ่านหน้าจอ
- หน้าด้านหลังเข้าถึงด้วยคีย์บอร์ดหรือโปรแกรมอ่านหน้าจอไม่ได้ขณะเปิด
- ปุ่ม × ขนาด 32 × 32px เกินพื้นที่กดขั้นต่ำ 24px

สิ่งที่ยังต้องทำเอง
- ใส่ DialogTitle เสมอ
- มีทางปิดที่มองเห็นได้ (× หรือปุ่มแบบ Cancel) ผู้ใช้โปรแกรมอ่านหน้าจอบนจอสัมผัสต้องใช้

## Tokens ที่ใช้

| Token | ใช้สำหรับ |
| ----- | --------- |
| `--popover` | พื้นหลังแผง |
| `--popover-foreground` | ตัวอักษรในแผง |
| `--foreground` | วงขอบ 1px รอบแผง ความทึบ 5% |
| `--muted-foreground` | ตัวอักษรคำอธิบาย ลิงก์ในคำอธิบายเปลี่ยนเป็น `--foreground` เมื่อชี้ |
| `--radius` | มุมของแผง: 2.6 × `--radius` (26px) |
| `--font-heading` | ฟอนต์หัวข้อ **แอปต้องกำหนดเอง** ไม่อยู่ใน token ที่ส่งมากับแพ็กเกจ |

ฉากหลังเป็นสีดำ 80% เบลอเล็กน้อย ไม่ใช่ token ซึ่งหนักกว่าการหรี่ 32% ของ Material มาก และไม่มีระบบที่ตรวจสอบระบบไหนใช้การเบลอ TODO: ตัดสินใจความเข้มของฉากหลัง และควรเป็น token เพื่อปรับตามธีมหรือไม่

ปุ่ม ×, ปุ่ม "Close" ในส่วนท้าย และ Button ที่ใส่ข้างในใช้ token ของ Button

หัวข้อ 16px medium คำอธิบาย 14px โหมดมืดตามคลาส `.dark` บน `<html>` หรือ element ที่ครอบหน้า

## ตัวอย่าง

จาก story `Playground` (`TransferDialog`) เขียนด้วยค่าเริ่มต้น กดปุ่มเพื่อเปิด

<Canvas of={DialogStories.Playground} />

```tsx
import {
  Button,
  Dialog,
  DialogClose,
  DialogContent,
  DialogDescription,
  DialogFooter,
  DialogHeader,
  DialogTitle,
  DialogTrigger,
  Input,
} from "@chonny_iamsrithong/lab-package"

<Dialog>
  <DialogTrigger render={<Button />}>Transfer funds</DialogTrigger>
  <DialogContent>
    <DialogHeader>
      <DialogTitle>Transfer funds</DialogTitle>
      <DialogDescription>
        Move money between your accounts. Transfers arrive instantly.
      </DialogDescription>
    </DialogHeader>
    <div className="grid gap-2">
      <label htmlFor="transfer-amount" className="text-sm font-medium">
        Amount
      </label>
      <Input id="transfer-amount" inputMode="decimal" placeholder="0.00" />
    </div>
    <DialogFooter>
      <DialogClose render={<Button variant="outline" />}>Cancel</DialogClose>
      <DialogClose render={<Button />}>Transfer</DialogClose>
    </DialogFooter>
  </DialogContent>
</Dialog>
```

เมื่อเปิด โฟกัสไปที่ช่อง Amount ซึ่งเป็น element แรกที่โฟกัสได้ ในฟอร์มจริงให้ครอบช่องและส่วนท้ายด้วยฟอร์ม และให้ Transfer เป็นปุ่มส่ง ดูหัวข้อ "ฟอร์มใน dialog"
