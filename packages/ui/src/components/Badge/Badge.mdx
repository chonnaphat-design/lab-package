# Badge

**วัตถุประสงค์:** ป้ายแคปซูลขนาดเล็กแบบอ่านอย่างเดียว บอกสถานะหรือหมวดหมู่ของสิ่งที่อยู่ข้าง ๆ

ระบบอื่นเรียกสิ่งนี้ว่า status label, tag หรือ lozenge ไม่ใช่ตัวเลขแจ้งเตือน และไม่ใช่สิ่งที่ให้กด

## ควรใช้เมื่อ

- **บอกสถานะของรายการ** ในลิสต์ ตาราง หรือส่วนหัว เช่น Paid, Pending, Draft, Archived, Overdue
- **บอกหมวดหมู่สั้น ๆ** ข้างหัวข้อ เช่น ชื่อแพ็กเกจหรือประเภท

## ไม่ควรใช้เมื่อ

| แทนที่จะใช้ badge กับ… | ให้ใช้ |
| ---------------------- | ------ |
| การกระทำที่ผู้ใช้กดเพื่อให้เกิดบางอย่าง | **Button** |
| ตัวกรองหรือตัวเลือกที่ลบได้ | TODO: ยังไม่มี component chip หรือ tag input |
| ตัวเลขยังไม่ได้อ่านหรือจุดแจ้งเตือนบนไอคอน | TODO: ยังไม่มี component counter Badge ไม่มีโหมดตัวเลขหรือจุด |
| ข้อความเกินสองคำ หรือเป็นประโยค | ข้อความธรรมดา |
| ข้อผิดพลาดของฟอร์ม | `invalid` ของ Input หรือ Textarea พร้อมข้อความข้างช่อง |
| ข้อความที่ผู้ใช้ต้องเห็นทันที | TODO: ยังไม่มี alert หรือ toast |

ใช้ badge แต่พอดี ถ้ามีเต็มหน้าจะไม่ดึงสายตาอีก และแต่ละส่วนของผลิตภัณฑ์ควรมีชุดสถานะที่จำกัดและตายตัว

## การเขียนข้อความบน badge

- **หนึ่งคำ ไม่เกินสองคำ** เช่น "Paid" หรือ "Partially refunded" ไม่ควรเกินประมาณ 20 ตัวอักษร
- **ใช้คำคุณศัพท์หรือรูปอดีต** ที่บอกสภาพ เช่น "Overdue", "Refunded" หลีกเลี่ยงคำกริยาที่อ่านเหมือนคำสั่ง เช่น "Refund"
- **ตัวพิมพ์แบบประโยค** เช่น "Partially refunded" ไม่ใช่ "PARTIALLY REFUNDED" ตัวพิมพ์ใหญ่ทั้งหมดอ่านยากกว่า
- **ความหมายอยู่ที่คำ ไม่ใช่สี** "Overdue" ต้องเข้าใจได้แม้เป็นสีเทา ถ้าคำเดียวไม่ชัด ให้เพิ่มบริบท เช่น "Payment: failed"
- **badge ไม่ตัดบรรทัดและไม่ถูกตัดข้อความ** ข้อความยาวทำให้ badge กว้างขึ้นและดัน layout ได้ TODO: ยังไม่กำหนดความกว้างสูงสุดหรือการตัดข้อความ

## การนำเข้าและใช้งาน

ติดตั้งแพ็กเกจ แล้วนำเข้า stylesheet **ครั้งเดียว** ที่ root ของแอป เช่น ใน `app/layout.tsx`

```bash
npm install @chonny_iamsrithong/lab-package
```

```tsx
import "@chonny_iamsrithong/lab-package/styles.css"
```

จากนั้นนำเข้า component ในไฟล์ที่ใช้

```tsx
import { Badge } from "@chonny_iamsrithong/lab-package"

<Badge variant="secondary">Pending</Badge>
```

- Badge ไม่มี `"use client"` และไม่ต้องมี ใช้ใน Server Component ได้

## Props และ variants

### `variant` รูปแบบ (ค่าเริ่มต้น `primary`)

| Variant | หน้าตา | ใช้ใน story กับ |
| ------- | ------ | --------------- |
| `primary` | พื้นเขียวมะนาวทึบ ตัวอักษรเขียวเข้ม | Paid |
| `secondary` | พื้นเทาอ่อนทึบ ตัวอักษรเข้ม | Pending |
| `outline` | พื้นจางมีเส้นขอบบาง | Draft |
| `ghost` | ไม่มีพื้น ตัวอักษรธรรมดา | Archived |
| `danger` | พื้นแดงอ่อน ตัวอักษรแดง | Overdue |
| `link` | ตัวอักษรเขียว ไม่มีพื้น | (ไม่มีตัวอย่างสถานะ) |

**variant บอกหน้าตา ไม่ได้บอกความหมาย** ยกเว้น `danger` ระบบที่โตแล้วตั้งชื่อสีของ badge ตามความหมาย คือ success, warning, info, error และ neutral ชุดของเรามีแค่ `danger`

- **ไม่มี success, warning หรือ info** ไม่มีอะไรใช้กับ "Due soon" (warning) หรือ "In review" (info)
- **`primary` คือเขียวมะนาวของแบรนด์ ไม่ใช่เขียวของความสำเร็จ** "Paid" ที่เป็น `primary` จึงอ่านเป็นการเน้นแบรนด์ มากกว่า "เสร็จแล้ว"

**`link`** ดูเหมือนลิงก์ (ตัวอักษรเขียว ไม่มีพื้น) อย่าใช้กับ badge ที่ไม่ใช่ลิงก์

### Props อื่น ๆ

| Prop | ค่าเริ่มต้น | ทำอะไร |
| ---- | ----------- | ------ |
| `render` | ไม่มี | แสดง badge เป็น element อื่น `render={<a href="…" />}` ทำให้เป็นลิงก์ ดูข้อควรระวังด้านล่าง |
| `aria-invalid` | ไม่มี | เพิ่มขอบแดง สำหรับ badge ที่แจ้งปัญหา เช่น "Missing" |
| `className` | ไม่มี | ปรับ layout เฉพาะจุด ควรใช้ variant มากกว่าการเปลี่ยนสไตล์ |

Badge **ไม่มี prop `size`** ทุกอันสูง 20px ตัวอักษร 12px น้ำหนัก medium ระยะขอบซ้ายขวา 8px รูปแคปซูล ไอคอนข้างในปรับเป็น 12px อัตโนมัติ ไอคอนวางก่อนข้อความ และต้องซ้ำความหมายของข้อความเท่านั้น

**badge ที่เป็นลิงก์:** GOV.UK และ IBM Carbon ไม่แนะนำ เพราะคนแยกไม่ออกว่า badge ไหนกดได้ ถ้าจำเป็น
- ทำให้ข้อความบอกจุดประสงค์ของลิงก์ชัดเจน
- เว้นระยะรอบ ๆ badge สูง 20px ต่ำกว่าพื้นที่กดขั้นต่ำ 24px จึงต้องห่างจากสิ่งที่กดได้อื่นพอสมควร

### สถานะ

| สถานะ | เมื่อ | หน้าตา |
| ----- | ----- | ------ |
| Hover | เฉพาะเมื่อเป็นลิงก์ | พื้นเข้มขึ้นเล็กน้อย `outline` และ `ghost` เป็นสีจาง `link` ขีดเส้นใต้ |
| Focus | โฟกัสลิงก์ด้วยคีย์บอร์ด | วงจาง 3px |
| Invalid | `aria-invalid` | ขอบแดง ไม่มีวง |

badge ที่ไม่ใช่ลิงก์จะไม่เปลี่ยนเมื่อชี้ ป้ายธรรมดาจึงไม่ดูเหมือนกดได้

โหมดมืดทำงานอัตโนมัติเมื่อมีคลาส `.dark` บน element ที่ครอบอยู่

### การเข้าถึง

- โปรแกรมอ่านหน้าจออ่าน badge เป็นข้อความธรรมดาตามลำดับในหน้า อย่าตั้งให้ badge ที่ไม่เปลี่ยนประกาศแบบสด TODO: ยังไม่มีแนวทางสำหรับ badge ที่เปลี่ยนสถานะขณะหน้าเปิดอยู่
- ความต่างของสีตัวอักษร วัดจาก badge จริง ตัวอักษร 12px ต้องได้ 4.5:1 ทุก variant ผ่าน

| Variant | สว่าง | มืด |
| ------- | ----- | --- |
| `primary` | 5.72 | 4.50 |
| `secondary` | 16.12 | 14.27 |
| `outline` | 18.43 | 17.34 |
| `ghost` | 19.59 | 18.90 |
| `danger` | 5.92 | 5.19 |
| `link` | 5.69 | 10.06 |

`primary` โหมดมืดผ่านพอดีไม่มีเผื่อ การเปลี่ยน `--primary` หรือ `--primary-foreground` ในโหมดมืดอาจทำให้ต่ำกว่า 4.5:1 ยังไม่ได้วัดสถานะตอนชี้ของ badge แบบลิงก์

## Tokens ที่ใช้

| Token | ใช้สำหรับ |
| ----- | --------- |
| `--primary` | พื้น `primary` และตอนชี้แบบลิงก์ |
| `--primary-foreground` | ตัวอักษร `primary` |
| `--secondary` | พื้น `secondary` และตอนชี้แบบลิงก์ |
| `--secondary-foreground` | ตัวอักษร `secondary` |
| `--foreground` | ตัวอักษร `outline` และผสมในสีตอนชี้ของ `primary` แบบลิงก์โหมดมืด |
| `--input` | พื้น `outline` |
| `--border` | ขอบ `outline` |
| `--muted` | พื้นตอนชี้ของ `ghost` และ `outline` แบบลิงก์ |
| `--muted-foreground` | ตัวอักษรตอนชี้ของ `ghost` และ `outline` แบบลิงก์ |
| `--destructive` | ตัวอักษรและพื้นจางของ `danger` และขอบตอน invalid |
| `--link` | ตัวอักษร `link` |
| `--ring` | วงโฟกัสของ badge แบบลิงก์ |
| `--radius` | ความโค้งมุม: 2.6 × `--radius` เป็นแคปซูล |
