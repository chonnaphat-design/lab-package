# Card

**วัตถุประสงค์:** กล่องที่รวมเนื้อหาและการกระทำเกี่ยวกับเรื่องเดียว เช่น สรุปบัญชี

## ควรใช้เมื่อ

- สรุปของสิ่งหนึ่งพร้อมข้อมูลและการกระทำไม่กี่อย่าง เช่น บัญชีพร้อมยอดเงินและปุ่ม Transfer
- dashboard หรือ feed ที่มีเนื้อหาหลากหลายให้เลื่อนดู
- ตัวเลือกไม่กี่อย่างให้ผู้ใช้เลือก แต่ละอันมีคำอธิบายสั้น ๆ

## ไม่ควรใช้เมื่อ

| แทนที่จะใช้ card กับ… | ให้ใช้ |
| --------------------- | ------ |
| รายการจำนวนมากแบบเดียวกันที่ผู้ใช้ค้นหาหรือเปรียบเทียบ | รายการหรือตาราง ข้อมูลเรียงตรงกันและอ่านเร็วกว่า Nielsen Norman Group เรียกการแทนรายการด้วย card ว่าเป็น anti-pattern |
| เนื้อหาก้อนเดียวในหน้า | เนื้อหาธรรมดาพร้อมหัวข้อ กล่องเพิ่มแค่น้ำหนักทางสายตา |
| card ซ้อนใน card | หัวข้อและระยะห่างภายใน card เดียว |
| ฟอร์มหรืองานที่ต้องการความสนใจ | ในหน้า หรือ **Dialog** |

## การเขียนเนื้อหา

- **หัวข้อ:** สั้นและเจาะจง บอกว่า card นี้เกี่ยวกับอะไร เช่น "Everyday account"
- **คำอธิบาย:** รายละเอียดสนับสนุนหนึ่งบรรทัด เช่น เลขบัญชีหรือวันที่
- **การกระทำ:** การกระทำหลักหนึ่งอย่าง ใช้คำกริยาและคำนาม เช่น "Transfer funds" วางการกระทำหลักที่ส่วนท้าย วางการกระทำที่มีอยู่ตลอดหรือสำคัญน้อย เช่น เมนูหรือ Edit ที่มุมขวาบนของส่วนหัว
- **ในตาราง card** วางข้อมูลสำคัญ เช่น ยอดเงิน ไว้ตำแหน่งเดียวกันทุก card

## ส่วนประกอบ

| ส่วน | หน้าที่ |
| ---- | ------- |
| **Card** | กล่อง: พื้นหลัง ขอบจาง มุมโค้ง ระยะขอบ |
| **CardHeader** | เก็บหัวข้อ คำอธิบาย และการกระทำ |
| **CardTitle** | หัวข้อ **ใส่ heading ไว้ข้างใน** ดูด้านล่าง |
| **CardDescription** | ข้อความสนับสนุนสีจางใต้หัวข้อ |
| **CardAction** | ช่องที่มุมขวาบนของส่วนหัว สำหรับปุ่มหรือเมนูหนึ่งอัน |
| **CardContent** | เนื้อหาหลัก |
| **CardFooter** | แถวด้านล่าง มักใช้วางปุ่ม |

## การนำเข้าและใช้งาน

ติดตั้งแพ็กเกจ แล้วนำเข้า stylesheet **ครั้งเดียว** ที่ root ของแอป เช่น ใน `app/layout.tsx`

```bash
npm install lab-package
```

```tsx
import "lab-package/styles.css"
```

จากนั้นนำเข้า component ในไฟล์ที่ใช้

```tsx
import {
  Card,
  CardAction,
  CardContent,
  CardDescription,
  CardFooter,
  CardHeader,
  CardTitle,
} from "lab-package"

<Card>
  <CardHeader>
    <CardTitle>
      <h3>Everyday account</h3>
    </CardTitle>
    <CardDescription>Account 1234 5678</CardDescription>
  </CardHeader>
  <CardContent>
    <p>$4,820.15</p>
  </CardContent>
</Card>
```

- นำเข้าเฉพาะส่วนที่ใช้
- Card ไม่มี `"use client"` และไม่ต้องมี ใช้ใน Server Component ได้
- กำหนด `--font-heading` ในแอป เพราะหัวข้อใช้ฟอนต์นี้

## หัวข้อและรายการ

- **หัวข้อต้องเป็น heading จริง** CardTitle เป็น `div` ที่จัดสไตล์ให้สิ่งที่อยู่ข้างใน จึงต้องใส่ `h2`, `h3` หรือระดับอื่นไว้ข้างใน ตามระดับที่เข้ากับหน้า อย่าข้ามระดับ หัวข้อที่แค่ดูเหมือน heading ไม่ผ่าน WCAG 1.3.1 TODO: CardTitle อาจแสดง heading เองได้
- **หลาย card คือรายการ** ครอบด้วย `ul` และ `li` ใส่ `aria-label` ให้รายการ และให้ทุก card มี heading ระดับเดียวกัน ตาม story `CardList` GitHub Primer และ Inclusive Components ทำแบบนี้
- **อย่าทำ card เป็น landmark** ใช้ `div` ตามเดิม โปรแกรมอ่านหน้าจอมี heading และรายการให้ใช้นำทางอยู่แล้ว

## Props และ variants

Card **ไม่มี prop `variant`** มีพื้นสีของ card ขอบจาง 1px มุมโค้ง 18px และไม่มีเงา เงาทำให้ดูเหมือนกดได้ และ IBM Carbon ไม่ใช้เงากับกล่องที่ไม่ได้กด

### Card

| Prop | ค่าเริ่มต้น | ทำอะไร |
| ---- | ----------- | ------ |
| `size` | `md` | `md`: ระยะขอบและระยะห่าง 24px `sm`: 16px สำหรับ layout ที่แน่น |
| `className` | ไม่มี | ปรับเฉพาะจุด เช่น ความกว้างหรือตำแหน่งในตาราง |

### CardHeader และ CardFooter

ใส่คลาส `border-b` ที่ส่วนหัว หรือ `border-t` ที่ส่วนท้าย เพื่อเพิ่มเส้นคั่น ระยะห่างข้างเส้นจะเท่ากับระยะขอบของ card ส่วนท้ายเป็นแถว เพิ่มช่องว่างระหว่างปุ่มด้วย `className`

### CardAction

ปุ่มหรือเมนูหนึ่งอันที่มุมขวาบนของส่วนหัว **ตั้งชื่อตาม card** เช่น `aria-label="More options for Savings goal"` เพื่อให้เข้าใจได้แม้อยู่นอกบริบท

### รูปภาพ

รูปที่เป็นลูกตัวแรกของ card จะเต็มขอบด้านบน ไม่มีระยะขอบด้านบน

- **รูปตกแต่ง:** `alt=""` ตาม story `WithImage`
- **รูปที่มีความหมาย:** อธิบายใน `alt` Inclusive Components แนะนำให้วางรูปที่มีความหมายไว้หลัง heading ในโค้ด แล้วใช้ CSS ย้ายขึ้นด้านบน เพื่อไม่ให้การนำทางด้วย heading ข้ามรูป สไตล์เต็มขอบของเราใช้ได้เฉพาะเมื่อรูปอยู่ก่อนในโค้ด TODO: ตัดสินใจว่าอะไรสำคัญกว่า

### Card ที่กดได้

ยังไม่มี card ที่กดได้ในตัว ถ้าทั้ง card เปิดสิ่งเดียว ให้ทำตาม story `ClickableCard`

- **ให้ heading เป็นลิงก์เดียว** และขยายให้เต็ม card ด้วย pseudo-element อย่าครอบ card ด้วยลิงก์ เพราะโปรแกรมอ่านหน้าจอจะอ่านทั้ง card เป็นชื่อลิงก์
- **แสดงโฟกัสที่ทั้ง card** ขณะลิงก์ได้โฟกัสจากคีย์บอร์ด ด้วยเส้นขอบทึบสีโฟกัส
- **อย่าใส่ปุ่มอื่น** หรือใส่น้อย ขนาดอย่างน้อย 24px และห่างกันพอ IBM Carbon ไม่อนุญาตเลย ส่วน Nielsen Norman Group และ Fluent อนุญาตการกระทำรอง แหล่งอ้างอิงเห็นต่างกัน
- **ข้อความใต้ลิงก์เลือก (select) ไม่ได้**

## ความต่างของสี

| อะไร | สว่าง | มืด | ต้องได้ |
| ---- | ----- | --- | ------- |
| ข้อความคำอธิบาย | 5.27 | 7.29 | 4.5 |
| เส้นโฟกัสของ card ที่กดได้ | 5.25 | 4.60 | 3 |
| ขอบ card เทียบกับหน้า | 1.25 | 1.26 | ดูด้านล่าง |

ขอบเป็นการตกแต่ง card ที่ไม่ได้กดระบุได้จากเนื้อหา WCAG 1.4.11 จึงไม่ต้องการ 3:1 แต่ถ้าวันหนึ่งขอบเป็นสัญญาณเดียวว่า card ถูกเลือกหรือกดได้ ก็จะต้องการ axe (WCAG 2.2 AA) ผ่านทุก story

## Tokens ที่ใช้

| Token | ใช้สำหรับ |
| ----- | --------- |
| `--card` | พื้นหลัง |
| `--card-foreground` | ข้อความ |
| `--foreground` | ขอบ ที่ 10% |
| `--muted-foreground` | ข้อความคำอธิบาย |
| `--border` | เส้นคั่นส่วนหัวและส่วนท้าย |
| `--radius` | มุม: 1.8 × `--radius` (18px) |
| `--font-heading` | ฟอนต์หัวข้อ **แอปต้องกำหนดเอง** |
