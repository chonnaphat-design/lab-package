# Checkbox

**วัตถุประสงค์:** ช่องที่ผู้ใช้ติ๊กเพื่อเปิดตัวเลือกหนึ่งตัว หรือเลือกกี่ตัวก็ได้จากรายการ

## ควรใช้เมื่อ

- **การยินยอมหนึ่งข้อ** เช่น "Email me my monthly statement" โดยค่าเริ่มต้นไม่ติ๊ก
- **ตัวเลือกอิสระกี่ตัวก็ได้** จากรายการสั้น ๆ เช่น จะรับการแจ้งเตือนอะไรบ้าง
- **"Select all"** เหนือรายการ แสดงเป็นติ๊กบางส่วนเมื่อเลือกไว้แค่บางตัว

การเลือกมีผลเมื่อส่งฟอร์ม

## ไม่ควรใช้เมื่อ

| แทนที่จะใช้ checkbox กับ… | ให้ใช้ |
| ------------------------- | ------ |
| เลือกได้หนึ่งตัวเท่านั้นจากหลายตัว | Radio button TODO: ยังไม่มี Radio |
| การตั้งค่าที่มีผลทันที เช่น โหมดมืด | Switch TODO: ยังไม่มี Switch |
| ตัวเลือกมากกว่าประมาณเจ็ดตัว | แบ่งรายการ หรือรายการที่ค้นหาได้ TODO: ยังไม่มี combobox |
| ข้อความที่ผู้ใช้ต้องยอมรับซึ่งเขียนเป็นปฏิเสธ | เขียนเป็นข้อความบอกเล่า เพื่อให้ติ๊กหมายถึง "ใช่" เสมอ |

## การเขียน label

- **บอกเล่าและสั้น** เช่น "Email me my monthly statement" หลีกเลี่ยงปฏิเสธ เช่น "Don't email me" ติ๊กต้องหมายถึงใช่เสมอ
- **คลิกได้ทั้ง label** ครอบ checkbox ด้วย `label` หรือชี้ `htmlFor` ของ `label` ไปที่ `id` ของ checkbox
- **ช่องอยู่ก่อน label** ทางซ้าย ช่วยผู้ใช้ที่ใช้โปรแกรมขยายหน้าจอ
- **กลุ่มตั้งเป็นคำถาม** เช่น "Which notifications do you want?" ใส่ไว้ใน `legend` ของ `fieldset` เพิ่มคำแนะนำ เช่น "Select all that apply" และอย่าติ๊กไว้ล่วงหน้า
- **รายการยาว:** เรียงแนวตั้ง ถ้าจำเป็น เพิ่มตัวเลือกสุดท้าย "None of these" หลังเส้นคั่น "or" ซึ่งจะล้างตัวเลือกอื่น

## การนำเข้าและใช้งาน

ติดตั้งแพ็กเกจ แล้วนำเข้า stylesheet **ครั้งเดียว** ที่ root ของแอป เช่น ใน `app/layout.tsx`

```bash
npm install @chonny_iamsrithong/lab-package
```

```tsx
import "@chonny_iamsrithong/lab-package/styles.css"
```

จากนั้นนำเข้า component ในไฟล์ที่ใช้

```tsx
import { Checkbox } from "@chonny_iamsrithong/lab-package"

<label className="flex items-center gap-3">
  <Checkbox name="statement" />
  Email me my monthly statement
</label>
```

- Checkbox มี `"use client"` มาในตัว จึงใช้จาก Server Component ได้ ถ้าอ่านค่าด้วย `checked` และ `onCheckedChange` ไฟล์ต้องขึ้นต้นด้วย `"use client"`
- ในฟอร์ม ให้ใส่ `name` ค่าที่ติ๊กจะถูกส่งไปกับฟอร์ม

## Props และ variants

Checkbox **ไม่มี prop `variant` หรือ `size`** ช่องขนาด 16 × 16px มุมโค้ง 6px มีพื้นที่กดที่มองไม่เห็นรอบช่อง ทำให้พื้นที่คลิกประมาณ 40 × 32px เกินขั้นต่ำ 24px และ label ยังเพิ่มพื้นที่อีก

| Prop | ค่าเริ่มต้น | ทำอะไร |
| ---- | ----------- | ------ |
| `defaultChecked` | `false` | ติ๊กไว้ตั้งแต่แรก |
| `checked` + `onCheckedChange` | ไม่มี | ให้แอปควบคุมว่าติ๊กหรือไม่ |
| `indeterminate` | `false` | ติ๊กบางส่วน: แสดงขีด และโปรแกรมอ่านหน้าจอได้ยิน "mixed" ใช้กับ "Select all" ที่ตัวเลือกถูกติ๊กแค่บางตัว ดู story `SelectAll` |
| `invalid` | `false` | สถานะผิดพลาด: ขอบและวงแดง โปรแกรมอ่านหน้าจอรู้ว่าผิด ต้องคู่กับข้อความผิดพลาดเสมอ |
| `disabled` | `false` | จาง 50% และเปลี่ยนไม่ได้ ดูด้านล่าง |
| `readOnly` | `false` | โฟกัสและอ่านได้ แต่เปลี่ยนไม่ได้ TODO: ยังไม่มีหน้าตาของตัวเอง |
| `required` | `false` | ส่งฟอร์มไม่ได้จนกว่าจะติ๊ก |
| `name`, `value` | ไม่มี | ชื่อฟิลด์ และค่าที่ส่งเมื่อติ๊ก |
| `id` | ไม่มี | id ที่ `htmlFor` ของ `label` ชี้มา |
| `className` | ไม่มี | ปรับเฉพาะจุด |

### ข้อผิดพลาด

- **ขอบแดงอย่างเดียวไม่พอ** ต้องมีข้อความผิดพลาด เช่น "Select at least one notification"
- **สำหรับกลุ่ม ให้แสดงข้อผิดพลาดครั้งเดียว** ที่กลุ่ม: ภายใน `fieldset` หลังคำแนะนำ เชื่อมด้วย `aria-describedby` ของ `fieldset` แทนการทำเครื่องหมายผิดที่ทุกช่อง

### ปิดใช้งานและอ่านอย่างเดียว

หลีกเลี่ยง checkbox ที่ปิดใช้งานเมื่อทำได้ ผู้ใช้โปรแกรมอ่านหน้าจอเข้าไม่ถึงจึงไม่รู้ว่าทำไมเปลี่ยนไม่ได้ Atlassian แนะนำให้ checkbox ยังใช้งานได้ และอธิบายด้วยข้อความแทน

ใช้ `readOnly` กับค่าที่ผู้ใช้เห็นแต่เปลี่ยนไม่ได้ เช่น ค่าที่ผู้ดูแลระบบตั้งไว้ ยังเข้าถึงด้วยคีย์บอร์ดได้ ใช้ `disabled` เฉพาะสิ่งที่ใช้ไม่ได้ชั่วคราวจนกว่าผู้ใช้จะทำอย่างอื่นก่อน

### Select all

checkbox "Select all" ติ๊กทุกตัวเลือกเมื่อคลิก และล้างทั้งหมดเมื่อคลิกอีกครั้ง ขณะที่ติ๊กไว้แค่บางตัว ให้ตั้ง `indeterminate` และย่อหน้าตัวเลือกไว้ใต้มัน ตาม story `SelectAll`

### สถานะ

| สถานะ | เกิดเมื่อ | หน้าตา |
| ----- | --------- | ------ |
| ไม่ติ๊ก | ค่าเริ่มต้น | ขอบสีเทา |
| ติ๊ก | คลิก หรือ `checked` | พื้นเขียวมะนาว เครื่องหมายถูกสีเข้ม และขอบสีเข้ม (ขอบเขียวมะนาวในโหมดมืด) |
| ติ๊กบางส่วน | `indeterminate` | พื้นเขียวมะนาว ขีดสีเข้ม |
| Focus | โฟกัสด้วยคีย์บอร์ด | ขอบเทาเข้มและวงจาง 3px ในทุกสถานะ |
| Invalid | `invalid` | ขอบแดงและวงแดงจาง |
| Disabled | `disabled` | จาง 50% เคอร์เซอร์ห้าม |

โหมดมืดทำงานอัตโนมัติเมื่อมีคลาส `.dark` บน element ที่ครอบอยู่ ช่องที่ไม่ติ๊กจะมีพื้นจาง ๆ

## ความต่างของสี

| อะไร | สว่าง | มืด | ต้องได้ |
| ---- | ----- | --- | ------- |
| ขอบช่องไม่ติ๊กเทียบกับหน้า | 5.27 | 8.43 | 3 |
| ขอบช่องที่ติ๊กเทียบกับหน้า | 8.77 | 10.06 | 3 |
| เครื่องหมายถูกหรือขีดบนพื้นเขียวมะนาว | 5.72 | 4.50 | 3 |
| ขอบโฟกัสเทียบกับหน้า | 5.25 | 4.60 | 3 |
| ขอบ invalid เทียบกับหน้า | 7.19 | 6.78 | 3 |

ขอบช่องไม่ติ๊กของ shadcn ใช้ `--input` ได้แค่ 1.23:1 เทียบกับหน้า สำหรับ checkbox ขอบนั้นเป็นสัญญาณเดียวว่ามี control อยู่ WCAG 1.4.11 จึงต้องการ 3:1 เราใช้ `--muted-foreground` แทน และให้ช่องที่ติ๊กมีขอบสีเข้มในโหมดสว่าง เพราะพื้นเขียวมะนาวอย่างเดียวได้แค่ 1.53:1 เทียบกับสีขาว axe (WCAG 2.2 AA) ผ่านทุก story

## Tokens ที่ใช้

| Token | ใช้สำหรับ |
| ----- | --------- |
| `--muted-foreground` | ขอบช่องไม่ติ๊ก |
| `--primary` | พื้นช่องที่ติ๊กและติ๊กบางส่วน และขอบในโหมดมืด |
| `--primary-foreground` | เครื่องหมายถูกและขีด และขอบช่องที่ติ๊กในโหมดสว่าง |
| `--input` | พื้นจาง ๆ ของช่องไม่ติ๊กในโหมดมืด ที่ 30% |
| `--ring` | ขอบโฟกัสและวงโฟกัส |
| `--destructive` | ขอบและวงตอน invalid |
