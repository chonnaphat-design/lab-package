# Input

**วัตถุประสงค์:** ช่องกรอกบรรทัดเดียวสำหรับค่าสั้น ๆ เช่น ชื่อ อีเมล จำนวนเงิน รหัสผ่าน หรือคำค้นหา

## ควรใช้เมื่อ

- ข้อความสั้นบรรทัดเดียว เช่น ชื่อ อีเมล จำนวนเงิน คำค้นหา URL เบอร์โทร รหัสผ่าน
- เลือกไฟล์อัปโหลดด้วย `type="file"`

## ไม่ควรใช้เมื่อ

| แทนที่จะใช้ input กับ… | ให้ใช้ |
| ---------------------- | ------ |
| ข้อความที่อาจยาวหลายบรรทัด เช่น โน้ต | **Textarea** |
| ช่องที่มีไอคอน ข้อความคงที่ หรือปุ่มอยู่ในกรอบ | **InputGroup** กับ InputGroupInput |
| รหัสครั้งเดียวหรือ PIN แบบช่องละตัว | **InputOTP** |
| การเลือกจากตัวเลือกที่กำหนดไว้ | TODO: ยังไม่มี Select, Radio หรือ Checkbox |
| ค่าที่ผู้ใช้ดูได้แต่แก้ไม่ได้และจะไม่คัดลอก | ข้อความธรรมดา |

## Label, คำแนะนำ และข้อผิดพลาด

Input เป็นแค่ช่องกรอก ไม่มี label คำแนะนำ หรือข้อความผิดพลาดในตัว ต้องใส่รอบ ๆ เอง TODO: ยังไม่มี component Field ที่รวมสิ่งเหล่านี้ไว้

- **Label มองเห็นได้เสมอ อยู่เหนือช่อง** ใช้ `<label htmlFor>` ชี้ไปที่ `id` ของช่อง ใช้ `aria-label` เฉพาะเมื่อจุดประสงค์ชัดโดยไม่ต้องมีคำ เช่น ช่องค้นหาข้างไอคอนแว่นขยาย
- **คำแนะนำ:** ประโยคสั้นหนึ่งประโยค เช่น "We'll only use this to send receipts" วางใต้ label ใส่ `id` แล้วชี้ `aria-describedby` ของช่องไปที่มัน
- **Placeholder ห้ามใช้แทน label หรือคำแนะนำ** มันหายไปทันทีที่พิมพ์ ใช้แค่เป็นตัวอย่างรูปแบบ หรือไม่ต้องใส่ Nielsen Norman Group, GOV.UK, IBM Carbon, Atlassian และ Microsoft Fluent เห็นตรงกัน
- **ข้อผิดพลาด:** `invalid` แค่เปลี่ยนขอบเป็นสีแดง ต้องมีข้อความบอกว่าต้องทำอะไรเสมอ เช่น "Enter an email address like name@acme.com" หลีกเลี่ยงคำว่า "invalid" และ "please"
  - วางข้อความข้างช่อง
  - ใส่ `id` ของข้อความใน `aria-describedby` ของช่อง เพื่อให้โปรแกรมอ่านหน้าจออ่านพร้อมกัน
  - เก็บสิ่งที่ผู้ใช้พิมพ์ไว้ ห้ามล้างช่อง
- **ตรวจเมื่อไร:** ตรวจตอนส่งฟอร์ม หรือตอนผู้ใช้ออกจากช่อง ไม่ใช่ระหว่างพิมพ์ แหล่งอ้างอิงเห็นต่างกันว่าแบบไหนดีกว่า ให้เลือกแบบเดียวทั้งผลิตภัณฑ์ TODO: ตัดสินใจ
- **จำเป็นหรือไม่จำเป็น:** บอกใน label เช่น "Phone (optional)" TODO: เลือกแนวทางเดียวทั้งผลิตภัณฑ์ ว่าจะทำเครื่องหมายช่องที่ไม่จำเป็น หรือช่องที่จำเป็น

## การนำเข้าและใช้งาน

ติดตั้งแพ็กเกจ แล้วนำเข้า stylesheet **ครั้งเดียว** ที่ root ของแอป เช่น ใน `app/layout.tsx`

```bash
npm install lab-package
```

```tsx
import "lab-package/styles.css"
```

จากนั้นนำเข้า component ในไฟล์ที่ใช้

```tsx
import { Input } from "lab-package"

<label htmlFor="email">Work email</label>
<Input id="email" type="email" autoComplete="email" spellCheck={false} />
```

- Input ไม่มี `"use client"` ในตัว ช่องในฟอร์มที่อ่านค่าตอนส่งใช้ใน Server Component ได้ ถ้าส่ง `onChange` หรือควบคุม `value` เอง ไฟล์ต้องขึ้นต้นด้วย `"use client"`

## Props และ variants

Input **ไม่มี prop `variant` หรือ `size`** ทุกช่องสูง 36px กว้างเต็มพื้นที่ ระยะขอบซ้ายขวา 12px รูปแคปซูล ตัวอักษร 16px บนหน้าจอแคบกว่า 768px เพื่อไม่ให้ iPhone ซูมเมื่อโฟกัส และ 14px ตั้งแต่ 768px

| Prop | ค่าเริ่มต้น | ทำอะไร |
| ---- | ----------- | ------ |
| `type` | `text` | ชนิดของค่า ดูหัวข้อ "การเลือก type" |
| `invalid` | `false` | สถานะผิดพลาด: ขอบและวงแดง โปรแกรมอ่านหน้าจอรู้ว่าช่องผิด ต้องคู่กับข้อความผิดพลาดเสมอ |
| `disabled` | `false` | จาง 50% กดหรือโฟกัสไม่ได้ |
| `readOnly` | `false` | เลือกและคัดลอกค่าได้ แต่แก้ไม่ได้ |
| `placeholder` | ไม่มี | ตัวอย่างที่แสดงตอนว่าง เป็นสีจาง ไม่ใช่ label |
| `autoComplete` | ไม่มี | บอกเบราว์เซอร์ว่าช่องนี้ไว้กรอกอะไร เช่น `"email"` หรือ `"name"` |
| `inputMode` | ไม่มี | แป้นพิมพ์ที่มือถือจะแสดง เช่น `"numeric"` หรือ `"decimal"` |
| `defaultValue` | ไม่มี | ค่าเริ่มต้น |
| `value` + `onChange` | ไม่มี | ให้แอปควบคุมค่าเอง |
| `className` | ไม่มี | ปรับ layout เฉพาะจุด เช่น ทำให้แคบลง |

attribute ปกติอื่น ๆ เช่น `name`, `required`, `spellCheck` และ `aria-describedby` ใช้ได้

### การเลือก type

- **อีเมล เบอร์โทร URL:** ใช้ `type="email"`, `"tel"` หรือ `"url"` มือถือจะแสดงแป้นที่เหมาะสม
- **ตัวเลข เช่น จำนวนเงินหรือเลขบัญชี:** ใช้ `type="text"` กับ `inputMode="decimal"` หรือ `"numeric"` GOV.UK ไม่แนะนำ `type="number"` เพราะมีปุ่มลูกศร ทำเลขยาวเพี้ยน และตัดเลขศูนย์นำหน้า story `Types` แสดง `type="number"` แต่ควรใช้ `inputMode`
- **ข้อมูลส่วนตัว:** ใส่ `autoComplete` กับช่องที่ถามเกี่ยวกับผู้ใช้ เช่น ชื่อ อีเมล เบอร์โทร ที่อยู่ บัตร WCAG 1.3.5 กำหนดไว้ และอย่าให้ผู้ใช้กรอกข้อมูลเดิมซ้ำในขั้นตอนเดียวกัน (WCAG 3.3.7)
- **ชื่อ อีเมล และเลขอ้างอิง:** ใส่ `spellCheck={false}`

### ความกว้าง

ช่องกว้างเต็มพื้นที่ที่วาง ถ้าค่าที่คาดไว้สั้น เช่น รหัสไปรษณีย์ รหัสหลังบัตร หรือปี ให้แคบลงเพื่อบอกความยาวที่คาด คนกรอกผิดมากขึ้นเมื่อมองไม่เห็นสิ่งที่พิมพ์ทั้งหมด TODO: ยังไม่มีตัวเลือกความกว้าง ให้ใช้ `className`

### สถานะ

| สถานะ | เกิดเมื่อ | หน้าตา |
| ----- | --------- | ------ |
| ว่าง | ยังไม่มีค่า | placeholder สีจาง |
| Focus | โฟกัสด้วยคีย์บอร์ด | ขอบเทาเข้มและวงจาง 3px |
| Invalid | `invalid` | ขอบแดงและวงแดงจาง |
| Disabled | `disabled` | จาง 50% เคอร์เซอร์ห้าม Tab ข้าม |
| Read-only | `readOnly` | เป็นข้อความธรรมดา: ไม่มีกรอบหรือพื้น เคอร์เซอร์ปกติ โฟกัสด้วยคีย์บอร์ดยังเห็นขอบเข้ม |

ช่อง **read-only** ดูเหมือนข้อความธรรมดา ผู้ใช้จึงไม่พยายามพิมพ์ IBM Carbon และ Shopify Polaris ก็ให้ช่อง read-only มีหน้าตาของตัวเอง ช่องยังโฟกัสได้ ผู้ใช้คีย์บอร์ดและโปรแกรมอ่านหน้าจอจึงยังเข้าถึง อ่าน และคัดลอกค่าได้ ใน InputGroup กลุ่มยังคงกรอบไว้ เหมาะกับช่องคัดลอกลิงก์

โหมดมืดทำงานอัตโนมัติเมื่อมีคลาส `.dark` บน element ที่ครอบอยู่

### ความต่างของสี

วัดจากช่องจริง

| อะไร | สว่าง | มืด | ต้องได้ |
| ---- | ----- | --- | ------- |
| ตัวอักษรที่พิมพ์ | 18.43 | 17.34 | 4.5 |
| Placeholder | 4.96 | 7.73 | 4.5 |
| ขอบโฟกัสเทียบกับหน้า | 5.25 | 4.60 | 3 |
| ขอบช่องเทียบกับหน้า | 1.23 | 1.48 | 3 ดูด้านล่าง |
| ขอบ invalid เทียบกับหน้า | 7.19 | 6.78 | 3 |

- **กรอบของช่องจางมาก** WCAG 1.4.11 ต้องการ 3:1 กับสิ่งที่บอกว่ามีช่องอยู่ตรงนั้น label ที่มองเห็นได้ข้างช่องอาจนับเป็นสัญญาณนั้น แต่คำอธิบายของ WCAG ยังกำกวม ให้มี label ที่มองเห็นได้ทุกช่อง TODO: ตัดสินใจว่าจะทำขอบ `--input` ให้เข้มขึ้นหรือไม่ ซึ่งมีผลกับทุกช่อง
- **ขอบแดงต้องไม่ใช่สัญญาณเดียวของข้อผิดพลาด** ใส่ข้อความผิดพลาดเสมอ

## Tokens ที่ใช้

| Token | ใช้สำหรับ |
| ----- | --------- |
| `--input` | ขอบ และพื้นที่ 30% |
| `--muted-foreground` | ตัวอักษร placeholder |
| `--foreground` | ตัวอักษรปุ่มเลือกไฟล์ |
| `--ring` | ขอบโฟกัสและวงโฟกัส |
| `--destructive` | ขอบและวงตอน invalid |
| `--radius` | ความโค้งมุม: 2.6 × `--radius` เป็นแคปซูล |

ตัวอักษรที่พิมพ์ใช้สีข้อความของหน้า

## ตัวอย่าง

จาก story `WithLabel` เขียนด้วยค่าเริ่มต้น

```tsx
import { Input } from "lab-package"

<div className="grid gap-2">
  <label htmlFor="input-email" className="text-sm font-medium">
    Work email
  </label>

</div>
```
