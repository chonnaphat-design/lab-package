# InputOTP

**วัตถุประสงค์:** ช่องกรอกรหัสครั้งเดียวแบบสั้น เช่น รหัสยืนยันที่ส่งทาง SMS แสดงทีละช่องต่อหนึ่งตัวอักษร

## ควรใช้เมื่อ

- รหัสยืนยันที่ส่งทาง SMS หรืออีเมล ปกติเป็นตัวเลข 6 หลัก
- รหัสยืนยันตัวตนสองขั้นตอนจากแอป authenticator

## ไม่ควรใช้เมื่อ

| แทนที่จะใช้ OTP input กับ… | ให้ใช้ |
| -------------------------- | ------ |
| รหัสผ่าน | **Input** กับ `type="password"` |
| PIN ลับที่ใช้ซ้ำและควรซ่อนขณะพิมพ์ | TODO: ยังไม่มีโหมดซ่อน InputOTP แสดงตัวอักษรเสมอ |
| ข้อความอิสระ หรือค่าที่ไม่รู้ความยาว | **Input** |
| รหัสยาว เช่น รหัสเข้าถึงหรือ license key 16 ตัว | **Input** พร้อมบอกรูปแบบใน label |

**แยกช่องหรือช่องเดียว?** GOV.UK, แนวทางของ Google Chrome และ Twilio แนะนำช่องข้อความธรรมดาช่องเดียวสำหรับรหัส การแยกช่องต่อหลักมักทำให้การวาง การกรอกอัตโนมัติ และโปรแกรมอ่านหน้าจอใช้ไม่ได้ InputOTP เลี่ยงปัญหานี้: ด้านหลังช่องที่เห็นคือ **ช่องจริงช่องเดียว** มี label เดียว Tab ครั้งเดียว และการวางกับการกรอกอัตโนมัติเติมได้ในครั้งเดียว ส่วน **Input** ที่มี label ชัดเจนก็ยังเป็นทางเลือกที่ง่ายกว่าและใช้ได้

## ส่วนประกอบ

| ส่วน | หน้าที่ |
| ---- | ------- |
| **InputOTP** | ช่องจริง เก็บค่า label และสถานะผิดพลาด รับการพิมพ์ การวาง และการกรอกอัตโนมัติ |
| **InputOTPGroup** | ช่องที่ต่อกันเป็นแถว |
| **InputOTPSlot** | ช่องหนึ่งช่อง แสดงตัวอักษรที่ตำแหน่ง `index` (นับจาก 0) เป็นแค่ภาพ |
| **InputOTPSeparator** | ขีดระหว่างสองกลุ่ม เช่น รหัสแบบ 3 + 3 เป็นแค่ภาพ ไม่ใช่ส่วนของค่า |

ทุกตำแหน่งตั้งแต่ 0 ถึง `maxLength − 1` ต้องมีช่องเดียวพอดี

## Label, คำแนะนำ และข้อผิดพลาด

InputOTP ไม่มี label คำแนะนำ หรือข้อความผิดพลาดในตัว ต้องใส่รอบ ๆ เอง

- **ใส่ label** แบบมองเห็นได้ เช่น "Security code" ชี้ไปที่ช่อง หรือใส่ `aria-label` บน InputOTP
- **คำแนะนำ:** บอกว่าส่งรหัสไปที่ไหนและยาวเท่าไร เช่น "Enter the 6-digit code from the text message we just sent" เชื่อมด้วย `aria-describedby` บน InputOTP แหล่งอ้างอิงเห็นต่างกันเรื่องการแสดงเบอร์โทรหรืออีเมล GOV.UK เลี่ยงตอนเข้าสู่ระบบ และ Visa เลี่ยงทั้งหมด
- **ข้อผิดพลาด:** ใส่ `invalid` บน InputOTP โปรแกรมอ่านหน้าจอจะรู้ว่ารหัสผิด และทุกช่องเป็นสีแดง ใส่ข้อความผิดพลาดเชื่อมด้วย `aria-describedby` ถ้อยคำของ GOV.UK
  - "Enter a correct security code"
  - "The security code has expired. We've sent you a new code"
  - "You've not entered enough numbers. The code must be 6 numbers"
- **หมดอายุและขอใหม่:** บอกผู้ใช้ว่ารหัสใช้ได้นานเท่าไร และมีทางขอรหัสใหม่ เช่น "Not received a text message?" พร้อมบอกว่าข้อความอาจใช้เวลาสักครู่ TODO: ยังไม่มีแนวทางสำหรับการขอรหัสใหม่หรือตัวจับเวลา

## การนำเข้าและใช้งาน

ติดตั้งแพ็กเกจ แล้วนำเข้า stylesheet **ครั้งเดียว** ที่ root ของแอป เช่น ใน `app/layout.tsx`

```bash
npm install @chonny_iamsrithong/lab-package
```

```tsx
import "@chonny_iamsrithong/lab-package/styles.css"
```

จากนั้นนำเข้า component ในไฟล์ที่ใช้

```tsx
"use client"

import { useState } from "react"
import { InputOTP, InputOTPGroup, InputOTPSlot } from "@chonny_iamsrithong/lab-package"

export function SecurityCode() {
  const [code, setCode] = useState("")
  return (
    <InputOTP
      maxLength={6}
      value={code}
      onChange={setCode}
      pattern="^\d+$"
      aria-label="Security code"
    >
      <InputOTPGroup>
        <InputOTPSlot index={0} />
        <InputOTPSlot index={1} />
        <InputOTPSlot index={2} />
        <InputOTPSlot index={3} />
        <InputOTPSlot index={4} />
        <InputOTPSlot index={5} />
      </InputOTPGroup>
    </InputOTP>
  )
}
```

- นำเข้าเฉพาะส่วนที่ใช้ เพิ่ม `InputOTPSeparator` สำหรับรูปแบบ 3 + 3
- InputOTP มี `"use client"` มาในตัว แต่ในทางปฏิบัติมักควบคุมค่าเองหรือใช้ `onComplete` ไฟล์ที่ใช้จึงขึ้นต้นด้วย `"use client"` ด้วย ตามตัวอย่าง

## Props และ variants

InputOTP **ไม่มี prop `variant` หรือ `size`** แต่ละช่องขนาด 36 × 36px ตัวอักษร 14px ช่องในกลุ่มต่อกัน และปลายกลุ่มเป็นรูปแคปซูล ทั้งแถวเป็นพื้นที่กดเดียว จึงเกินขั้นต่ำ 24px มาก และมือถือไม่ซูมเมื่อโฟกัส

### InputOTP

| Prop | ค่าเริ่มต้น | ทำอะไร |
| ---- | ----------- | ------ |
| `maxLength` | จำเป็น | จำนวนตัวอักษร ต้องเท่ากับจำนวนช่อง ปกติคือ 6 |
| `value` + `onChange` | ไม่มี | ให้แอปควบคุมค่าเอง story ใช้แบบนี้เสมอ |
| `onComplete` | ไม่มี | ทำงานเมื่อกรอกช่องสุดท้ายเสร็จ ดูหัวข้อ "การส่งรหัส" |
| `pattern` | ไม่มี | regular expression ที่ค่าทั้งหมดต้องตรง: `"^\\d+$"` สำหรับตัวเลข `"^[a-zA-Z0-9]+$"` สำหรับตัวอักษรและตัวเลข อย่างอื่นจะถูกปฏิเสธ |
| `invalid` | `false` | สถานะผิดพลาด: บอกโปรแกรมอ่านหน้าจอว่ารหัสผิด และทำให้ทุกช่องเป็นสีแดง ต้องคู่กับข้อความผิดพลาด |
| `pasteTransformer` | ตัดช่องว่างและขีดออก | ปรับข้อความที่วางก่อนตรวจ ดูหัวข้อ "การวาง" ส่งฟังก์ชันของตัวเองเพื่อเปลี่ยนได้ |
| `disabled` | `false` | ทำให้ช่องจาง 50% และหยุดรับการกรอก |
| `inputMode` | `numeric` | แป้นพิมพ์ที่มือถือแสดง ตั้งเป็น `"text"` สำหรับรหัสที่มีตัวอักษร |
| `autoComplete` | `one-time-code` | ให้มือถือเสนอรหัสจาก SMS ควรคงไว้ |
| `aria-label` | ไม่มี | **จำเป็นเมื่อไม่มี label ที่มองเห็นได้** เช่น "Security code" |
| `aria-describedby` | ไม่มี | เชื่อมคำแนะนำและข้อความผิดพลาดกับช่อง |

### InputOTPSlot

| Prop | ค่าเริ่มต้น | ทำอะไร |
| ---- | ----------- | ------ |
| `index` | จำเป็น | ช่องนี้แสดงตัวอักษรตัวที่เท่าไร นับจาก 0 |
| `aria-invalid` | ไม่มี | ทำให้ช่องนี้ช่องเดียวเป็นสีแดง ปกติใช้ `invalid` บน InputOTP แทน |

### การวาง

วางรหัสทั้งชุดจะเติมทุกช่อง ผู้ใช้ต้องวางหรือกรอกรหัสอัตโนมัติได้เสมอ ตาม WCAG 3.3.8

รหัสที่คัดลอกจากข้อความมักมีช่องว่างหรือขีด InputOTP ตัดสิ่งเหล่านี้ออกจากข้อความที่วางก่อนตรวจกับ `pattern` ตามที่ GOV.UK แนะนำ "428 193", "428-193", "428–193" และ " 428193 " จึงกลายเป็น 428193 ตัวอักษรที่ `pattern` ไม่อนุญาต เช่น ตัวอักษรในรหัสที่เป็นตัวเลขอย่างเดียว ยังทำให้การวางทั้งหมดถูกปฏิเสธ

### การส่งรหัส

`onComplete` ส่งรหัสได้ทันทีที่กรอกช่องสุดท้ายเสร็จ เร็วก็จริง แต่ถ้าพิมพ์ผิดหรือวางผิดจะถูกส่งทันทีและเสียสิทธิ์ลองไปหนึ่งครั้ง WCAG 3.2.2 ไม่อนุญาตการเปลี่ยนแปลงที่ผู้ใช้ไม่คาดคิด ให้มีปุ่ม "Continue" ที่มองเห็นได้ หรือบอกผู้ใช้ล่วงหน้าว่ารหัสจะส่งอัตโนมัติ TODO: ตัดสินใจกฎของผลิตภัณฑ์

### การกรอกรหัสจาก SMS อัตโนมัติ

ถ้าต้องการให้ iPhone เสนอรหัสจาก SMS ให้บรรทัดสุดท้ายของข้อความเป็นแบบ `@example.com #123456` โดยใช้โดเมนของเว็บไซต์ Chrome อ่านรหัสได้ผ่าน WebOTP API ทั้งสองอย่างตั้งค่าที่แอปและผู้ส่งข้อความ ไม่ใช่ที่ component นี้

### สถานะ

| สถานะ | เกิดเมื่อ | หน้าตา |
| ----- | --------- | ------ |
| Active | ช่องที่ตัวอักษรถัดไปจะเข้าไป | ขอบโฟกัสเข้มและวงจาง 3px ช่องว่างที่ active มีเคอร์เซอร์กะพริบ |
| Invalid | `invalid` | ขอบแดง และวงแดงจางรอบกลุ่มและช่องที่ active |
| Disabled | `disabled` | ทั้งช่องจาง 50% |

โหมดมืดทำงานอัตโนมัติเมื่อมีคลาส `.dark` บน element ที่ครอบอยู่

โปรแกรมอ่านหน้าจอได้ยินช่องเดียวพร้อม label และค่า ช่องที่เห็นและขีดระหว่างกลุ่มถูกซ่อนจากโปรแกรมอ่านหน้าจอ

## Tokens ที่ใช้

| Token | ใช้สำหรับ |
| ----- | --------- |
| `--input` | ขอบของช่อง และพื้นที่ 30% |
| `--ring` | ขอบและวงของช่องที่ active |
| `--destructive` | ขอบและวงตอน invalid |
| `--foreground` | เคอร์เซอร์กะพริบ |
| `--radius` | ปลายกลุ่ม: 2.6 × `--radius` เป็นแคปซูล |

ตัวอักษรที่พิมพ์ใช้สีข้อความของหน้า
