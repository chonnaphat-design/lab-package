# Textarea

**วัตถุประสงค์:** ช่องกรอกหลายบรรทัดสำหรับข้อความอิสระที่อาจยาวเกินหนึ่งบรรทัด เช่น โน้ต คำอธิบาย หรือข้อความถึงผู้รับ

## ควรใช้เมื่อ

- ข้อความอิสระที่อาจต้องใช้หลายบรรทัด เช่น โน้ตถึงผู้รับ คำอธิบายปัญหา ข้อความ

## ไม่ควรใช้เมื่อ

| แทนที่จะใช้ textarea กับ… | ให้ใช้ |
| ------------------------- | ------ |
| ค่าสั้นบรรทัดเดียว เช่น ชื่อ เบอร์โทร จำนวนเงิน | **Input** |
| คำตอบที่มีโครงสร้าง เช่น ที่อยู่ หรือการเลือกจากตัวเลือก | Input หลายช่อง หรือ control สำหรับเลือก TODO: ยังไม่มี Select, Radio หรือ Checkbox |
| กล่องข้อความที่มีปุ่มติด เช่น แนบไฟล์และส่ง | **InputGroup** กับ InputGroupTextarea |
| ข้อความที่มีการจัดรูปแบบ | TODO: ยังไม่มี rich-text editor |

GOV.UK แนะนำให้หลีกเลี่ยงคำถามปลายเปิดกว้าง ๆ แบ่งเป็นคำถามเฉพาะเจาะจงเมื่อทำได้

## Label, คำแนะนำ และข้อผิดพลาด

Textarea เป็นแค่ช่องกรอก ไม่มี label คำแนะนำ ข้อความผิดพลาด หรือตัวนับตัวอักษรในตัว ใส่แบบเดียวกับ Input

- **Label:** มองเห็นได้เสมอ อยู่เหนือช่อง ใช้ `<label htmlFor>` ชี้ไปที่ `id` ของ textarea
- **คำแนะนำ:** ประโยคสั้นหนึ่งประโยคใต้ label เชื่อมด้วย `aria-describedby` ถ้ามีจำกัดความยาว ให้บอกตรงนี้ เช่น "Up to 500 characters"
- **Placeholder:** ห้ามใช้แทน label หรือคำแนะนำ มันหายไปเมื่อผู้ใช้พิมพ์
- **ข้อผิดพลาด:** `invalid` ทำให้ขอบแดง ต้องมีข้อความผิดพลาดข้างช่องเสมอ เชื่อมด้วย `aria-describedby`

## การนำเข้าและใช้งาน

ติดตั้งแพ็กเกจ แล้วนำเข้า stylesheet **ครั้งเดียว** ที่ root ของแอป เช่น ใน `app/layout.tsx`

```bash
npm install lab-package
```

```tsx
import "lab-package/styles.css"
```

จากนั้นนำเข้า component ในไฟล์ที่ใช้

```tsx
import { Textarea } from "lab-package"

<label htmlFor="note">Note to recipient</label>
<Textarea id="note" rows={5} />
```

- Textarea ไม่มี `"use client"` ในตัว ในฟอร์มที่อ่านค่าตอนส่งใช้ใน Server Component ได้ ถ้าส่ง `onChange` หรือควบคุม `value` เอง ไฟล์ต้องขึ้นต้นด้วย `"use client"`

## Props และ variants

Textarea **ไม่มี prop `variant` หรือ `size`** กว้างเต็มพื้นที่ สูงอย่างน้อย 64px (หรือเท่ากับ `rows` บรรทัด) ระยะขอบ 12px มุมโค้ง 14px ตัวอักษร 16px บนหน้าจอแคบกว่า 768px เพื่อไม่ให้มือถือซูมเมื่อโฟกัส และ 14px ตั้งแต่ 768px

| Prop | ค่าเริ่มต้น | ทำอะไร |
| ---- | ----------- | ------ |
| `rows` | ไม่มี | ความสูงเริ่มต้นเป็นจำนวนบรรทัด เพื่อบอกความยาวคำตอบที่คาด GOV.UK ใช้ 5 เป็นค่าเริ่มต้น และ 8 สำหรับคำตอบที่ยาวกว่า |
| `invalid` | `false` | สถานะผิดพลาด: ขอบและวงแดง โปรแกรมอ่านหน้าจอรู้ว่าช่องผิด ต้องคู่กับข้อความผิดพลาดเสมอ |
| `disabled` | `false` | จาง 50% เคอร์เซอร์ห้าม |
| `readOnly` | `false` | แสดงเป็นข้อความธรรมดา ยังโฟกัส อ่าน และคัดลอกได้ แต่แก้ไม่ได้ |
| `placeholder` | ไม่มี | ตัวอย่างที่แสดงตอนว่าง เป็นสีจาง ไม่ใช่ label |
| `defaultValue` | ไม่มี | ข้อความเริ่มต้น |
| `value` + `onChange` | ไม่มี | ให้แอปควบคุมข้อความเอง |
| `spellCheck` | ตามเบราว์เซอร์ | เบราว์เซอร์ตรวจคำสะกดใน textarea ใส่ `false` กับรหัสหรือข้อความอ่อนไหว เพราะบางเบราว์เซอร์ส่งข้อความไปยังบริการตรวจคำ |
| `className` | ไม่มี | ปรับ layout เฉพาะจุด |

attribute ปกติอื่น ๆ เช่น `name`, `required` และ `aria-describedby` ใช้ได้

### ความสูง

- **เริ่มที่ `rows` บรรทัด** หรือ 64px ถ้าไม่ได้ตั้ง `rows` ตั้งตามความยาวคำตอบที่คาด ตามที่ GOV.UK, Microsoft Fluent และ Apple แนะนำ `rows={3}` สูง 86px และ `rows={6}` สูง 146px
- **ขยายตามเนื้อหา** ขณะผู้ใช้พิมพ์
- **หยุดขยาย** ที่ประมาณ 17 บรรทัด (384px) หรือครึ่งหน้าจอบนจอเล็ก แล้วเลื่อนภายในช่อง ปุ่มด้านล่างจึงยังอยู่บนหน้าจอ Shopify Polaris, Atlassian และ GitHub Primer ทำแบบเดียวกัน
- **เบราว์เซอร์รุ่นเก่า** ที่ขยายช่องตามเนื้อหาไม่ได้ จะให้ผู้ใช้ลากเพื่อขยายความสูงแทน การขยายตามเนื้อหาต้องใช้ Chrome 123, Safari 26.2 หรือ Firefox 152 ขึ้นไป

ในเบราว์เซอร์ปัจจุบันผู้ใช้ลากปรับขนาดไม่ได้ เพราะช่องปรับขนาดเอง

### คีย์บอร์ด

- **Enter** ขึ้นบรรทัดใหม่ อย่าให้ Enter ส่งฟอร์มจาก textarea ให้ใช้ปุ่มส่ง ถ้าเพิ่มทางลัด เช่น Ctrl/Cmd+Enter ให้คงปุ่มไว้ด้วย
- **Tab** ไปช่องถัดไปตามปกติ

### สถานะ

| สถานะ | เกิดเมื่อ | หน้าตา |
| ----- | --------- | ------ |
| ว่าง | ยังไม่มีค่า | placeholder สีจาง |
| Focus | โฟกัสด้วยคีย์บอร์ด | ขอบเทาเข้มและวงจาง 3px |
| Invalid | `invalid` | ขอบแดงและวงแดงจาง |
| Disabled | `disabled` | จาง 50% เคอร์เซอร์ห้าม |
| Read-only | `readOnly` | เป็นข้อความธรรมดา: ไม่มีกรอบหรือพื้น เคอร์เซอร์ปกติ โฟกัสด้วยคีย์บอร์ดยังเห็นขอบเข้ม |

ข้อความ read-only ดูเหมือนข้อความธรรมดา ผู้ใช้จึงไม่พยายามพิมพ์ ช่องยังโฟกัสได้ จึงยังเข้าถึง อ่าน และคัดลอกได้

โหมดมืดทำงานอัตโนมัติเมื่อมีคลาส `.dark` บน element ที่ครอบอยู่

### ความต่างของสี

สีเดียวกับ Input ตัวอักษรที่พิมพ์ placeholder ขอบโฟกัส และขอบแดงตอน invalid ผ่านทั้งหมด กรอบของช่องจาง อยู่ที่ 1.23:1 เทียบกับหน้าสีขาว จึงต้องมี label ที่มองเห็นได้ทุก textarea TODO: ตัดสินใจว่าจะทำขอบ `--input` ให้เข้มขึ้นหรือไม่ ดูคู่มือของ Input

## Tokens ที่ใช้

| Token | ใช้สำหรับ |
| ----- | --------- |
| `--input` | ขอบ และพื้นที่ 30% |
| `--muted-foreground` | ตัวอักษร placeholder |
| `--ring` | ขอบโฟกัสและวงโฟกัส |
| `--destructive` | ขอบและวงตอน invalid |
| `--radius` | ความโค้งมุม: 1.4 × `--radius` (14px) |

ตัวอักษรที่พิมพ์ใช้สีข้อความของหน้า
